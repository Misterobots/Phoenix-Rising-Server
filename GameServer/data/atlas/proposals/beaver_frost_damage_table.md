# Proposal: frost Gnasher damage rows (ours, not game data)

**This is a proposal by this project. None of these rows exist in Dauntless 2.1.1.** The numbers are derived
from real rows of the same family by two stated rules, so each one can be traced and changed. They have not been
tried in play.

Data: [`beaver_frost_damage_table.json`](beaver_frost_damage_table.json), generated by
`python -m tools.atlas.proposals.beaver_frost_damage`. Each row has a `_proposal` block naming its model row, the
rule and the attack that uses it.

## The problem

In the 2.1.1 client the frost Gnasher (`beaver_frost`) inherits `DamageComp.DamageTable = beaver_damage_table`, the
normal Gnasher's physical/terra table. Nothing changes it at runtime: the native lookup
(`ArchonBehemoth.GetDamageInfo`) reads only that table, then `DamageTable_Generic`. Its frost attacks name 17 rows
that are in neither, and in no other table of the game, except three that only other behemoths have. Without them:

- **Belly dive:** only the `bite_lunge` window can damage. The body slam window (`BellyDive_Slam`) and the 800-radius
  slam area effect deal nothing.
- **Belly drift, somersault, ice spike, ice toss, shoulder drop:** their windows and area effects deal nothing.
- A window whose row is missing still counts as the target's one hit for the montage, so touching the empty slam can
  also stop a later hit in the same attack.

The live game ran behemoth damage on its own servers, whose data we do not have, so it may have had these rows.
(`verified.json`: `frost-gnasher-missing-rows`.)

## Rules

- **Swap:** take the model row and turn its elemental amount (flame, or terra) into frost. Physical damage, damage
  type, stagger and camera-shake tags stay as in the model.
- **Aether:** total damage × 1.2, the increase added as frost, physical unchanged. 1.2 is the median total increase
  of the game's base/aether pairs (thunderbird `LightSlam` 1.11 and 1.17, mantis `spin_attack_aoe_fwd` 1.33 and 1.2,
  wolf_frost `JumpSlam` 1.2). The frost wolf's pair, 200/50 → 200/100, is the only frost pair and fits exactly.

Models come from the blaze Gnasher (`beaver_blaze_damage_table`) first: it is the sister elemental variant with the
same threat level (9) and the same base attacks. Hellion and the frost Pangar fill in rows the Gnasher tables lack.

ordinary tail slam (Medium stagger). The ice projectile comes from a threat-11 behemoth (frost Pangar alpha), so it
may be strong for a threat-9 one.

## Optional: frost versions of rows the frost Gnasher already has

In 2.1.1 the frost Gnasher's shared attacks (tail tantrum, tail slam, tail slash, bite lunge, …) use the normal
Gnasher's terra rows. The JSON's `optional_frost_versions_of_shared_rows` has frost versions made from the blaze
Gnasher's rows of the same name. Using them changes 2.1.1 behaviour (more elemental damage, frost instead of terra),
so they are kept apart.

## Using it on the server

The rows are table inputs, like any `DamageTableData` row: they go through the damage formula
(`topics/armor.md`) and the threat/tuning scaling (`topics/behemoth_scaling.md`) like the game's own. A server can
give `beaver_frost` a table made of `beaver_damage_table` plus `missing_rows` (and optionally the frost versions),
looked up before `DamageTable_Generic`.
